# PPT HTML-first 生成流水线

当前 PPTAgent 采用与 `example/` 一致的三阶段模型流程：先一次性完成全局策划，再按页进行视觉设计和 HTML 执行，最后统一渲染与导出。运行时不使用固定主题模板或程序化页面回退。

## 1. 完整流程

1. **资料预处理**：读取用户描述和附件，标准化为 Markdown，并提取与页面相关的文本、表格、图表和本地资产索引。
2. **全局大纲**（`outline`）：模型一次生成整套 `DeckOutlineSpec`，包括页数、叙事顺序、每页结论、全局风格和唯一调色板。确定性 adapter 随后派生页面角色、布局锁、内容密度合同和渲染合同。
3. **逐页视觉规划**（`style`）：每页在已经锁定的布局族内生成 `SlideDesignPlan`，明确阅读顺序、内容结构、关键视觉、字号、间距和安全区。
4. **逐页 HTML 执行**（`designer`）：模型根据批准内容和视觉方案生成单页 `HtmlSlideSpec`。本地图标在服务端替换为受信任 SVG，HTML/CSS 经安全清理后交给 Chromium。
5. **质量检查**：Chromium 检查固定画布、根节点、字体、边界、溢出、遮挡和语义框；内容检查核对标题、已批准文案、数字和页码。设计、内容和几何问题记录为质量告警，由提示词引导模型避免；安全边界、单一根节点和 1600×900 画布仍是硬要求。
6. **渲染与导出**：每页渲染为 3200×1800 PNG，再以一页一张全幅图片组装为 16:9 PPTX，并输出质量报告和导出清单。

## 2. 并行策略

全局大纲、调色板和布局锁在并行展开前一次确定。页面之间最多并行 4 页；单页内部的视觉规划、HTML 生成、安全清理和浏览器检查保持串行。

默认 4 页并发是在当前模型上的质量/速度平衡：相较 6 页并发，它降低长响应超时和结构化输出截断概率，同时仍能显著缩短 8–20 页演示的总耗时。可通过 `PPT_SLIDE_CONCURRENCY` 调整；浏览器渲染并发由 `PPT_BROWSER_CONCURRENCY` 独立控制，默认 3。

## 3. 约束边界

硬约束只用于不可妥协的运行边界：

- 禁止脚本、远程资源、危险 URL、越界选择器和不受信任 HTML/SVG；
- 每页仅一个 `.slide` 根节点；
- 固定 1600×900 逻辑画布；
- 必须使用已批准的本地字体、图标和全局颜色 token。

以下问题不再阻断生成，只进入 `quality-report.json` 作为 warning，并通过生成提示词进行软约束：

- 字号、标题行数、内容密度和卡片数量；
- 越界、滚动、重叠、遮挡和留白失衡；
- 标题或批准文案的呈现质量；
- DOM、SVG、阴影和 CSS 复杂度预算。

这种边界允许模型保留设计自由，同时让问题可观测、可追踪，避免程序规则把可以正常使用的页面直接判失败。

## 4. 产物目录

每个任务写入 `apps/runtime/artifacts/decks/<task-id>/`：

- `previews/page-XXX.html`：最终清理后的单页 HTML；
- `previews/page-XXX.png`：2 倍分辨率页面预览；
- `reports/quality-report.json`：按页诊断和告警汇总；
- `reports/export-manifest.json`：PPTX 结构、图片哈希和可打开性检查；
- `exports/deck.pptx`：最终图片型演示文稿。

PPTX 当前是高保真图片型产物，不提供元素级编辑。导出清单必须确认页数正确、每页恰好一张全幅图片且文件可打开。
